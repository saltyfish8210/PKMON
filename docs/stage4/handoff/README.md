# 交接目录（所有人看这一页）

> 规矩：**代码走分支，资料走这里。** 不要用微信/网盘传文件，也不要口头说"我做完了"。

## 一、两种交接路径

| 类型 | 放哪儿 | 下家怎么拿 |
|---|---|---|
| 代码（组件、接口实现、脚本） | 分支 **stage3**（本轮迭代集成分支） | `git fetch origin && git checkout stage3 && git pull` |
| 资料（接口说明、样例 JSON、坐标表、验收截图清单） | `docs/stage4/handoff/` | 同上，拉下来直接看文件 |
| 接口样例 JSON | `docs/stage4/handoff/examples/` | 一个接口一个文件，文件名 = 接口路径的短名，如 `capture-nearby.json` |
| 假数据（下家先用它开发） | `docs/stage4/handoff/mocks/` | 文件名 = 用途，如 `nearby.json`、`track.json` |

**为什么不用 main**：main 目前落后 stage3 共 138 个提交，本轮迭代统一在 stage3 上集成，12-10 之后再合回 main。

## 二、每份交接资料必须包含

1. **给谁**：写清接收人姓名（一个人或多个人）。
2. **什么时候给的**：日期。
3. **怎么用**：三行以内能照着做的示例（代码片段或 curl 命令）。
4. **验收标准**：下家怎么判断"我拿到了且能用"。

## 三、文件命名

`<交接项>-<交付人>.md`，例如：

- `map-component-闫昕.md`：地图组件怎么用
- `api-contract-孙虹毅.md`：接口清单与样例
- `track-api-董欣毓.md`：轨迹接口
- `pack-script-胡豪.md`：打包脚本
