记录三：工作区回退事故与恢复（11/02 凌晨前发现）
====================================================
问题：10/31 成果合入后，工作区文件被回退到旧版本（foundation 文件在磁盘上
被删、配置被退回旧版），但 HEAD 停在新分支；若此时提交会把成果以「删除」
形式提交。
处理：AI 用 git diff HEAD 证明全部改动仅为回退、无新增内容，经本人确认后
以 git restore 从 HEAD 恢复工作区；成果在 origin/main 上未受影响。
教训写回：切换分支前后必须 git status 核对；不批量丢弃「看起来像旧的」文件。

====================================================
质量反思
====================================================
- AI 擅长把已有结论快速组织成规范文档与图，但会「顺水推舟」把未发生的
  过程写成按时完成，本人需专门核对时间与状态表述；
- 代码类输出必须跑真实测试再采信；文档类输出必须核对引用路径与提交号；
- 教训：关键操作（合入主线、恢复工作区）前后各留一次 git status / log 证据，
  本次事故即靠 reflog 与 diff 得以无损恢复。
