2. dev 文件库重启持久化（核心验收：重启后记录仍在）
   方法：mvn package 构建 jar，dev profile 启动（jdbc:h2:file:./data/pkmon-dev），
   走真实 HTTP 流程后停服重启再查。脚本与本条日志留存于本机沙盒目录，关键输出如下：
     register code=0 → login code=0 → dev spawn code=0（DEV_SIMULATED）
     → challenge code=0（questionId=hello_world_001，选项 A,B,C，响应不含 correctOptionId）
     → answer code=0 result=CORRECT captureRecordId=a1847f72-...
     → summary 重启前 captureCount=1 collected=1/1
     → study task code=0 taskId=aef868ec-... status=WAITING
     —— 停服（停前等 3 秒，越过 H2 MVStore 后台落盘窗口 WRITE_DELAY=500ms）——
     → 重启后 users/me code=0（同 token，会话仍在）
     → 重启后 summary captureCount=1 collected=1/1（收录仍在）
     → 重启后 current task 为同一 taskId（自习任务仍在）
   结论：通过。会话、收录记录、自习任务三类数据重启后均保留。
   限制：验证用 Stop-Process 强杀模拟停机，已加落盘等待；kill -9 瞬间（<500ms 内）
   的末次写入丢失属于 H2 崩溃场景，不在「正常重启保留」范围内。
   dev 库为开发库，含历史测试残留数据，不作为干净环境证据；干净空库迁移由第 1 项
   （CommonFoundationTest 空库迁移断言）覆盖。
