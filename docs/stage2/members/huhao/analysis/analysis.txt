2 系统边界与参与者
====================================================
系统边界：PKMon 第二阶段 = Flutter 客户端 + Spring Boot 服务端 + 嵌入式数据库。
客户端不直连数据库；数据层只对服务端可见（见 diagrams/系统模块包图.png）。

与本范围相关的参与者：
- 终端用户：发起业务请求，只感知统一响应信封；
- 各业务模块作者（闫昕/孙虹毅/董欣毓/赵冠钧）：调用公共类型、注入 Clock、
  提出表结构与配置需求；
- 构建/展示执行者（本人与读者）：按启动说明构建、启动、核对环境；
- 测试作者（李宗晏）：把唯一约束与持久化语义转化为验收用例。

3 典型场景（正常与异常）
====================================================
S1 服务启动与环境核对
  正常：空数据库启动 → 自动执行 V1 迁移 → 启动检查输出 profile、数据源 URL、
        已应用迁移 → /test/hello 可达。
  异常：数据库不可用或迁移校验失败 → 启动直接失败（fail-fast），不带着
        半初始化状态对外服务。
S2 请求处理与统一响应
  正常：业务成功 → {"code":0,"message":"ok","data":{...}}。
  异常：请求形状不合法（缺参/类型不匹配/JSON 无法解析）→ 400 + 40001；
        路径不存在 → 404 + 40401；未捕获异常 → 500 + 50000，
        堆栈只记服务端日志，不下发客户端。
S3 时间相关规则的独立验证
  正常：各模块注入 java.time.Clock，生产为 UTC 系统时钟；
        测试替换为固定时钟即可验证过期等边界，不依赖 sleep。
  异常：直接调用系统时间的代码无法离线验证边界 → 分析结论为禁止，
        由可注入 Clock 收口（设计轮落实）。
S4 数据写入与并发唯一性
  正常：业务数据按外键与约束落库。
  异常：同一遭遇重复收录、同一 requestId 重复作答 → 由数据库唯一约束
        兜住（(userId,spawnId)、requestId），先查后写在并发下不可靠，
        不能只靠客户端禁用按钮。

4 对象识别与职责（本人重点对象）
====================================================
- ApiResponse：统一响应信封（code/message/data），成功与失败的唯一对外形状。
- GlobalExceptionHandler：异常响应兜底，业务模块自己的处理器优先，
  其余全部映射为统一信封，不泄露内部细节。
- Clock：时间来源抽象，全模块统一注入，测试可替换。
- Repository 接口：业务模块定义、数据层装配实现；业务代码不出现 SQL。
- 数据库实体：users / auth_sessions / species / questions / spawns /
  challenges / answer_attempts / capture_records（本阶段最小覆盖）；
  study_tasks / location_samples 待驻留字段定稿后增补。
- 迁移（Migration）：schema 版本化载体，只增不改，由本人统一编号。

各对象的方法签名与字段在设计轮定型，见 design/design.txt、
design/interfaces.json 与 design/analysis-to-design.csv。

5 主要数据关系
====================================================
见 diagrams/核心数据关系图.png。要点：
- User 是归属主体：AuthSession / StudyTask / Spawn / CaptureRecord 均归属用户；
- StudyTask 驻留达标最多产生一次 Spawn；Spawn 最多对应一个进行中 Challenge；
- Challenge 每次作答产生一条 AnswerAttempt（requestId 为幂等键）；
- 答对结算产生 CaptureRecord，(userId, spawnId) 唯一保证不重复收录；
- Species / Question 为共享目录数据，正确答案只在服务端可见。

6 模块依赖规则（分析级）
====================================================
单向依赖：web → service → repository(接口) → 数据层；domain 被各层引用
但不依赖技术层。禁止：客户端直连数据库；业务模块互读对方数据表；
user 反向依赖 capture/study；业务代码读取 X-Dev-User 等开发替身。
（设计轮细化见 design/design.txt 第 4 节与 diagrams。）
