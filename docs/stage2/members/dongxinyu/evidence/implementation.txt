三、端到端冒烟（真实 HTTP，内存存储，替身遭遇）

启动：
java -jar target/pkmon-server-0.1.0.jar \
  --server.address=127.0.0.1 --server.port=18418 \
  --pkmon.capture.dev-user-header=true \
  --pkmon.study.rules.required-seconds=5

脚本：~/study_smoke.py（本机副本 D:\work\study_smoke.py），输出 evidence/implementation-smoke.txt

步骤与实测：
1. POST /api/v1/study/tasks → 200，status=WAITING，requiredSeconds=5
2. 第 1 条样本 → 200，sampleAccepted=true，仍 WAITING
3. 第 2 条样本 → 200，status=DWELLING，effectiveSeconds=0
4. 第 3 条样本（间隔 6 秒 ≥ 阈值 5）→ 200，status=TRIGGERED，effectiveSeconds=5，spawnId 非空
5. GET /api/v1/study/tasks/current → 200，返回 TRIGGERED 任务（触发后仍是活动任务）
6. POST .../end → 200，status=ENDED，保留 effectiveSeconds 与 spawnId
7. 结束后再提交样本 → 409，code=40903
8. 他人结束该任务 → 404，code=40401

四、实现中修正的两个问题（均已复测）

1. DwellState.isActive 原先把 TRIGGERED 排除，导致触发后 current 查不到任务、也能再开新任务；
   改为"除 ENDED 外均为活动"。TC-S05 与冒烟第 5 步覆盖。
2. StudyExceptionHandler 通过 @Bean 注册但没有优先级，被 common 的全局兜底吞成 500；
   加 @Order(HIGHEST_PRECEDENCE) 后 40903/40401 正确返回。冒烟第 7、8 步覆盖。

五、已知限制（不得写成已完成）

1. 存储是 InMemoryTaskRepository：进程重启数据丢失，唯一约束靠 synchronized 近似，不是数据库约束。
2. 身份来自 capture 的 X-Dev-User 请求头替身；未设该开关时接口返回 50301，认证接入后必须替换。
3. 遭遇由 StubSpawnGateway 只生成 UUID 并打 WARN 日志，没有写入 spawn 表，也没有挑战与判题。
4. 区域中心使用候选坐标（39.9042, 116.4074），未按赵冠钧的真实中心点配置；启动日志有 WARN。
5. 未做并发触发测试、未接 MySQL、未做真机与客户端联调。
