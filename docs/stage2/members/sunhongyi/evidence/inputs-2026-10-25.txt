二、因此改了什么（本轮唯一需要改代码的一项）
====================================================================
2.1 开发期开关的安全默认
  原状：pkmon.capture.dev-user-header 与 pkmon.capture.dev-spawn-enabled 默认 true，
    即任何环境启动都开放身份替身与开发遭遇入口。
  改为：两个开关默认值由 profile 决定——激活 dev 或 test profile 时默认开启，其余（含无 profile、
    prod）默认关闭；仍可用同名属性显式覆盖。开启时在启动日志打 WARN，避免“悄悄开着”。
  in-memory-store 保持默认 true：真实持久化实现接入前若关闭它，本模块没有可用仓储，应用起不来。
    这一条在代码注释里写明，属于已知的过渡状态。
  代码位置：server/src/main/java/edu/pkmon/capture/config/CaptureConfig.java

2.2 补的测试（胡豪要求的“启动与拒绝测试”）
  新增 3 个测试类、11 个用例：
    CaptureSwitchTest（5 个）：未接入认证一律 50301；关闭开发遭遇时 40301 且不创建机会；
      无 profile 默认关闭；dev/TEST 默认开启且大小写不敏感；prod/staging 不视为开发环境。
    CaptureDefaultProfileHttpTest（3 个，@SpringBootTest + MockMvc，无 profile）：
      业务接口 503/50301；开发遭遇入口同样拒绝；旧演示接口不受影响（200）。
    CaptureDevProfileHttpTest（3 个，@ActiveProfiles("dev")）：
      带身份头可正常访问；缺身份头仍 401/40101（不因 profile 放宽校验）；开发遭遇可用且
      sourceType=DEV_SIMULATED。
