# PKMon 作图规范（团队规则 v1.0）

> 适用：所有 OOA/OOD 图（用况图、类图、顺序图、状态图、包图、活动图）。
> 依据：课程课件 6 份原文 + OMG UML 2.5.1 / Microsoft Learn / Sparx EA / Visual Paradigm 公开规范。
> 逐条缺陷与判断见同目录 `作图规范与缺陷清单.md`（41 处缺陷、26 张逐张判定）。
> 本文只写"必须怎么做"，是评审与提交的检查依据。

## 0 三条铁律

1. **一张图只表达一个图种、一个视角**。不得混入构件矩形、数据库圆柱、ER 鸦爪、自造图种名（"导航图""迁移图""核心数据关系图"）。
2. **图上只出现模型元素**。不得写人名、"（本人）""主责：××"、文档路径（`analysis/…`）、环境限定（"仅 dev/test"）。
3. **命名统一**：用况图、参与者、类图、顺序图、状态图、包图、活动图；"用例"仅用于"测试用例"。

## 1 分图种规则（摘）

| 图种 | 必须做到 | 禁止 |
|---|---|---|
| 用况图 | 参与者画人形（人员）/设备或外系统符号；系统边界框内放用况椭圆；参与者—用况=实线**无箭头无标签**；用况之间只用 `«include»`/`«extend»` 虚线 | 把软件、题库、服务器时间当参与者；用况间带箭头实线；用况名里写环境 |
| 类图 | 三栏（类名/属性/操作）；类型位只写类型；关联两端标多重性；关联名写动词短语；依赖用虚线 + `«use»`；实现用虚线 + 空心三角 | 类型位写取值或业务键；空心菱形聚合误用；一条线分叉连多类；类体写人名或叙述句 |
| 顺序图 | 生命线写 `对象 : 类`；参与者画人形；消息同步=实心箭头、返回=虚线开放箭头；有激活条；分支用 `alt`/`else`/`loop`/`opt`/`critical` 并写 `[监护]` | 生命线写系统边界或 URL；无激活条；用 `==` 分隔多场景；跳线返回 |
| 状态图 | 初态实心圆、终态双圈；状态内 `entry/do/exit` 成栏；内部转移写状态栏内；复合状态必须有子初态；转移格式 `事件[监护]/动作` | 初态出转移带监护；自环代替内部转移；无终止状态的死状态；把中文句子当状态名 |
| 包图 | 文件夹符号；包间依赖=虚线 + `«import»`/`«access»`；包内只放类型名 | 包内画构件/圆柱；实线箭头当关联；空心三角当实现；包名带人名 |
| 活动图 | 初/终态、动作圆角矩形、判定菱形、分支写 `[监护]` | 把判定画成动作；菱形无两个出边；泳道与标题混用 |

## 2 通用规则

- **多重性**：`1`、`0..1`、`1..*`、`0..*`，标在靠近被修饰类的一端。
- **约束**：唯一/只读等写成 `{unique}`、`{readonly}`，不要自造 `«唯一»`。
- **注记**：用折角矩形 + 虚线连到被说明的元素；注记里可以写规则与边界，不写人名。
- **图名与图注**：图内标题与正文图题一致；图注只解释"这张图表达什么"，不替代正文分析。

## 3 提交前检查清单（12 条，逐条打勾）

1. 图种名是否与文档章节目录一致（用况/类/顺序/状态/包/活动）？
2. 是否一张图只有一个图种、一个视角？
3. 图上是否出现人名、文档路径、环境限定？
4. 参与者是否都是系统外部的人/设备/外系统？
5. 参与者与用况之间是否无箭头、无标签？
6. 用况之间关系是否都有 `«include»`/`«extend»`？
7. 类框是否三栏、类型位是否只写类型？
8. 每条关联两端是否都有多重性？
9. 顺序图生命线是否 `对象 : 类`、是否都有激活条？
10. 状态图是否初/终态齐全、复合状态是否有子初态？
11. 包图依赖是否全部虚线且标 `«import»`/`«access»`？
12. 图内标题、正文图题、文件名是否一致？

## 4 流程约定（本次新增，长期有效）

1. **先出规格再画图**：新图先写"节点清单 + 连线/多重性"，评审通过后再画（模板见《作图规范与缺陷清单》第 5 节）。
2. **图源入库**：合规图统一放 `docs/stage3/diagrams/`，命名 `fig-<章>-<序号>-<图种>-<主题>.png`。
3. **提交前跑守卫**：`python docs/stage3/check_diagrams.py` 必须输出 PASS；它检查文档里每张图都指向合规目录、文件存在、且在图件登记表中。
4. **AI 生成图同样受约束**：AI 起草的 puml/图必须由本人逐条对照第 3 节清单复核后才能入库。
5. **历史材料**：已经讲过的 PPT 不追改备注；图体更新时在图注或附录说明"图为规范版"。

## 5 与文档标准的关系

《软件工程文档标准·面向对象分析设计文档》要求每种图配"综述 + 元素描述 + 关系描述"；图本身按本规范画，文字描述仍按该模板填写。两者缺一不可。
